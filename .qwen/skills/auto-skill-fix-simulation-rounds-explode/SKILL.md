## Problem
The simulation runner calculates total rounds from LLM-generated `time_config`:

```python
total_rounds = int(total_hours * 60 / minutes_per_round)
```

The LLM can generate large values like `total_simulation_hours: 168` (7 days) with `minutes_per_round: 30`, resulting in **336 rounds**. This causes the round counter to display `40/336` and makes the simulation too long for the high per-round LLM cost.

## Root Cause
In `simulation_config_generator.py`, the `_generate_time_config()` prompt allows:
- `total_simulation_hours`: 24–168 hours (LLM defaults to 168 for sustained topics)
- `minutes_per_round`: 30–120 minutes (30 gives more rounds)
- No explicit instruction to keep total rounds low

The user-visible `max_rounds` slider in Step 2 has a **custom-mode toggle** that is off by default, so users see the full LLM-generated rounds unless they manually switch.

## Calculation Chain
1. **LLM generates** `time_config` JSON with `total_simulation_hours` and `minutes_per_round`
2. **Runner computes** `total_rounds = total_hours * 60 / minutes_per_round`
3. **User can override** with `max_rounds` slider in Step 2 (but custom mode is off by default)
4. **Truncation** happens only if `max_rounds` is explicitly provided → **users get the full LLM-generated value**

### Truncation logic (in `simulation_runner.py`)
```python

if max_rounds is not None and max_rounds > 0:
    original_rounds = total_rounds

```

## Hermes Python Encoding Issue (Windows)
The hermes-agent Python virtual environment (`C:\Users\sensong\AppData\Local\hermes\hermes-agent\venv\`) has `utf8_mode=0`, meaning `sys.flags.utf8_mode == 0`. This causes Python to use `cp936` (GBK) as the default source encoding instead of UTF-8, leading to `SyntaxError: invalid character` on any `.py` file containing Chinese characters in docstrings, comments, or string literals.

**Fix:** Add `-X utf8` flag to the Python command in `package.json`:
```json
"backend": "cd backend && uv run python -X utf8 run.py"
```

**Symptom:** `SyntaxError: invalid character '（' (U+FF08)` or similar Chinese punctuation errors on files that are otherwise valid UTF-8.

**Note:** `-X utf8` only affects the startup process of the Python interpreter; it does not affect subprocesses spawned by the running application.
